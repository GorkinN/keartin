# Риски и узкие места

## 12 ГБ VRAM

- FP16 Flux не влезет (~31 ГБ в сборе).
- FP8 впритык.
- Рабочий коридор: NF4 + CPU offload или GGUF Q5/Q6.
- Пик во время VAE-decode тоже считать, не только загрузку transformer.
- Windows CUDA-контекст Ollama может **не отдать** память сразу после `keep_alive: 0`. Нужен poll + повторный stop, не вера в один вызов.

## Одновременная работа Ollama и Flux

Гарантия только через:

1. `asyncio.Lock` в GpuManager
2. проверку `ollama ps`
3. порог `nvidia-smi`

Любой прямой вызов Ollama в обход GpuManager — баг. Правило в `.cursorrules`.

## Контекст 16k у 9B-модели

KV-кэш на полном окне съест карту. Жёсткий `num_ctx=8192`. Оценка RAG: top_k=10 × ~600 токенов ≈ 6k + system — влезает.

## FB2 / EPUB

- Пространства имён FictionBook.
- EPUB как zip с битым HTML.
- Сноски и встроенная графика.

Парсер обязан возвращать мягкую ошибку на файл, не валить всю библиотеку. EPUB: только spine, выкидывать nav/css. FB2: `body` + `title-info`, без binary/cover.

## Русский язык

- LLM: Qwen — приемлемо.
- Embed: только bge-m3, не nomic-embed-text.
- Промпт для Flux — **английский**, отдельным шагом. Русский промпт в Flux даёт хуже картинки.

## Долгие операции

Индексация книги 100+ страниц не должна блокировать HTTP.

Схема: HTTP 202 + job status + SSE/poll. Чанки и эмбеды батчами, чтобы UI видел прогресс («стр. 40/400»).

Генерация картинки на 4070: ориентир 30–60+ секунд на 1024×1024.

## SQLite и большие тексты

Посты мелкие — полный текст в SQLite нормален. PDF/EPUB десятки МБ в SQLite не класть.

## bitsandbytes на Windows

Исторически ломкий. Этап 2 сразу закладывает GGUF-fallback в тот же GpuManager, не «потом когда-нибудь».

## Лицензия FLUX.1-dev

Non-commercial. Для личного локального использования ок. В корневом README написать явно.

## 32 ГБ системной RAM

NF4 offload держит часть весов в RAM + 9B в Ollama + Qdrant + Chrome. Терпимо, если **не** держать Flux в VRAM «на всякий случай».

## Гонки джоб

Два параллельных generate: второй должен ждать lock или получить 409. Не стартовать второй Flux.

## Кэш Hugging Face не на D:

Без `HF_HOME` библиотеки пишут в `%USERPROFILE%\.cache\huggingface` на диске C:. Повторно качается Flux (~десятки ГБ), `bge-m3` уезжает не туда, системный диск забивается.

Проверка на этапе 0: в процессе `ai-service` `HF_HOME` = `D:/huggingface_cache`. На этапах 2 и 3 — загрузка не создаёт второй кэш в профиле пользователя.

## Окружение Windows (зафиксировано на этапе 0)

- Docker Desktop должен быть запущен: без pipe `dockerDesktopLinuxEngine` compose не стартует.
- Образ `minio/minio` с Docker Hub на этой машине недоступен (`pull access denied`). В compose — `quay.io/minio/minio`.
- `corepack enable` не пишет в `D:\nodejs`. JS-скрипты — через `npx pnpm@9.15.9`.
- Системный Python 3.14 не используем для venv: слишком новый для будущего torch. Venv — 3.12.
