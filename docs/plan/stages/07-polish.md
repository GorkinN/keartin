# Этап 7. Полировка

**Статус:** не начат  
**Зависимости:** [этап 6](06-frontend.md)  
**Следующий:** стабильная v1, новые фичи только по отдельному запросу

## Цель

Поведение «как продукт», без новых подсистем. Закрыть UX, ошибки, логирование, краевые случаи GPU.

## Что делается

- CRUD пресетов довести: валидация описания и few-shot, пустой пресет нельзя сохранить криво.
- Отмена job: abort Ollama stream; если Flux ещё не стартовал — не стартовать; если стартовал — политика «дождаться и пометить cancelled» или аккуратный interrupt, зафиксировать в ARCHITECTURE.
- Человекочитаемые ошибки:
  - Ollama недоступна
  - VRAM не освободилась
  - пустой RAG в режиме `rag`
  - битый файл книги
  - MinIO/FS недоступен
- Структурные логи Python и Nest.
- UX: кнопки disable, пока `GET /gpu/status` busy.
- Seed картинки в UI (показать / скопировать / задать при regenerate).
- Два параллельных generate: второй ждёт или 409 — одно поведение, описать в UI.
- Дописать `docs/ARCHITECTURE.md`, `docs/GPU.md`, `docs/RAG.md` по факту кода.
- Обновить статус в [README плана](../README.md).

## Файлы

Точечные правки уже существующих модулей. Новых сервисов нет.

## Решения этапа

- Не добавлять auth, очередь Redis, Docker для GPU, ComfyUI, редактор поста.
- Не менять дефолтный сторадж без запроса.

## Как проверяется

Чеклист приёмки v1:

- [ ] Большая книга индексируется с прогрессом, UI живой.
- [ ] Regenerate image only не трогает текст.
- [ ] Regenerate text only не обязана сразу трогать картинку.
- [ ] Удаление книги чистит Qdrant и storage.
- [ ] Toggle `STORAGE_DRIVER=s3` работает (хотя бы вручную через env).
- [ ] Два параллельных generate не запускают два Flux.
- [ ] После картинки `nvidia-smi` близок к idle, `ollama ps` пуст.
- [ ] Ошибка «Ollama выключена» понятна в UI.
- [ ] Отмена во время текста не оставляет вечный job `running`.

## Критерий приёмки

Можно пользоваться приложением для реальной генерации постов без curl и без ручной чистки VRAM.
