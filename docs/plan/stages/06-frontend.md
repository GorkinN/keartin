## Отчёт

### Сделано

- Четыре экрана на Vite: библиотека, мастер поста, история, пресеты. Sidebar вместо верхней навигации. Браузер ходит только на `:5173`, прокси на Nest. CORS не включался.
- `GET /posts/:id/image` отдаёт PNG через StorageProvider. В `<img>` кэш сбрасывается через `updatedAt`. Пустой ключ или нет файла — `404`, в карточке текст «Картинка не найдена».
- Мастер: источники → параметры → стрим на том же экране. Размер — квадрат, портрет 4:5, 16:9, 9:16, черновик 512 и свой размер (256–1024, кратно 16). В запрос уходит `steps: 20`.
- SSE закрывается на `image_done`, на `text_done` при повторе текста и на `error`.

### Как проверить

Нужны Vite `:5173`, Nest `:3000`, FastAPI `:8000`, Qdrant. Картинка в браузере видна при том `STORAGE_DRIVER`, которым пост был записан.

1. Загрузить книгу и дождаться «готово».
2. Создать пресет.
3. Сгенерировать пост: токены, затем прогресс картинки, затем превью. Пост сам попадает в историю.
4. Открыть папку.
5. Перегенерировать картинку — текст тот же, seed новый.
6. Удалить пост. Список истории без него, чужие посты на месте.

Проверено в браузере 2026-09-23: пустая библиотека, пресет «этап6-проверка», свой размер 1000 блокирует кнопку («Ширина должна делиться на 16»), TXT до `ready 1/1`, пост S / 512×512 / 20 steps со стримом токенов и превью, повтор картинки до `15/20` и новый PNG при том же тексте, «Проводник открыт», удаление этого поста. Пост, записанный в MinIO, при текущем `fs` показывает «Картинка не найдена». Повтор только текста в этом прогоне не нажимался: та же кнопка и тот же хук, конечное событие `text_done`.

### Не вошло

Отмена джобы, toasts, индикатор занятого GPU, seed в форме, потолок 1024, редактор markdown. Это этап 7.

## Цель

Четыре рабочих экрана, стриминг текста и прогресс картинки. Без WYSIWYG-редактора.

## Экраны

1. **Библиотека** — загрузка книг, список, статус индексации, удаление, переиндексация.
2. **Создание поста** — мастер: источники → параметры (тема, тон, длина, эмодзи, структура, режим RAG, пресет, цитируемость) → генерация.
3. **История** — список, просмотр, открыть папку, удаление.
4. **Пресеты** — CRUD.

## Что делается

- React Router, каркас sidebar + страницы.
- shadcn/ui: Button, Card, Select, Switch, Textarea, Dialog, Progress, Tabs, Sidebar.
- TanStack Query для REST.
- `EventSource` / хук `useSse` для джобы генерации.
- Превью текста по мере токенов.
- Прогресс картинки.
- Кнопки «перегенерировать текст» / «перегенерировать картинку».
- «Открыть папку».
- Пустые состояния и ошибки API.
- Длина S / M / L (ориентир 500 / 1200 / 2500 символов).

## Решения этапа

- Тема: нейтральная светлая/тёмная shadcn default.
- Соцсеть не хардкодится.
- Проверка в браузере обязательна: не только скриншот, а клики по потоку.
- FastAPI из браузера не вызывается.

## Что сознательно не делается

- Полировка copy, toasts, отмена job, GPU-busy индикатор — можно набросать, но довести на этапе 7.
- Редактор markdown.

## Как проверяется (браузер)

1. Загрузить книгу, дождаться `ready`.
2. Создать пресет.
3. Сгенерировать пост: видны токены, затем прогресс картинки, затем превью.
4. Сохранение → запись в истории.
5. Открыть папку.
6. Перегенерировать только картинку — текст тот же.
7. Перегенерировать только текст.
8. Удалить пост и книгу.
9. Проверить, что состояние библиотеки и истории согласовано.

Желательно глянуть desktop-ширину; мобильная вёрстка не цель v1, но sidebar не должен ломать layout.

## Критерий приёмки

Пользователь без curl проходит путь «книга → пост с картинкой → история».
