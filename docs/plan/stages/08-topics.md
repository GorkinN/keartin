# Этап 8. Темы из сети и оглавления

## Отчёт

### Сделано

- `POST /topics`, `GET /topics`, `DELETE /topics/:id`. Область уходит в RSS Google News. Книги дают пункты `Book.outline`. Чанки в сеть не отправляются.
- Успешный ответ LLM (8–12 тем, тенант `llm`) пишется в `TopicSearch`. Пустой RSS, обрыв сети и сбой модели строку не создают.
- Экран «Темы». Клик по теме открывает мастер с заполненным полем. Пункт оглавления в библиотеке и в мастере делает то же.
- Подпись «GPU занят» на экране тем кнопку поиска не выключает.

### Как проверить

Нужны Vite `:5173`, Nest `:3000`, FastAPI `:8000`, Ollama. Картинка и очередь постов не менялись.

1. `node backend/test/units.ts` — разбор RSS: заголовки, пустой канал, HTML в title.
2. `pytest ai-service/tests/test_topics_rank.py` — 8–12 тем, мусор даёт ошибку, вызов через `acquire("llm")`.
3. `tsc` backend и frontend без ошибок.
4. `POST /topics` с областью «привычки» → 8–12 тем. Повторный заход берёт `GET /topics` и в RSS не ходит.
5. Пустой RSS → «По этому запросу заголовков не нашлось.», новой строки нет.
6. Клик по теме и по пункту оглавления заполняют поле мастера.

Проверено 2026-10-04: миграция `20261004130000_topic_search`, юниты RSS, 7 тестов Python, `tsc` backend и frontend. `POST /topics` с областью «привычки» вернул `201` и 12 тем за ~60 с; до этого при выключенном FastAPI тот же запрос дал «Модель не собрала список тем.», и список остался пустым. Короткая область — `400`, чужая книга — `404`. Экран «Темы» показывает книги и пустой список, кнопка без ввода выключена. `/create?topic=…` открывает «Параметры» с заполненным полем.

### Не вошло

Озвучка, музыка, видео, публикация, свой список RSS-лент, новый тенант GPU.

## Цель

Помочь выбрать тему поста до генерации. Источники: заголовки из интернета и уже собранное оглавление книги. Картинку, VRAM и пайплайн поста не удлиняем.

## Что делается

- Браузер говорит только с Nest. Nest сам забирает заголовки: RSS выбранных лент и/или поиск без API-ключа. В интернет уходит короткий запрос. Текст книги и чанки RAG наружу не отправляются.
- Пользователь задаёт область («привычки», «история Рима») или указывает книги библиотеки. Запрос по книгам собирается локально из оглавления, не из полного текста.
- Стоящая LLM под `acquire("llm")` отбирает 8–12 тем на русском и коротко поясняет, почему тема годится для поста. Пустой ответ поиска — понятная ошибка.
- Список тем сохраняется в SQLite, чтобы не искать заново при каждом заходе.
- Клик по теме открывает мастер поста с заполненным полем. Пункт оглавления в библиотеке делает то же: сейчас оглавление только показывается в [frontend/src/components/book-outline.tsx](../../../frontend/src/components/book-outline.tsx).
- Публикацию поста наружу не делаем.

## Микро-план

### Источник заголовков

Один источник, без ключа: RSS-поиск Google News.

`https://news.google.com/rss/search?q={area}&hl=ru&gl=RU&ceid=RU:ru`

Запрос в URL — только область пользователя после trim (2–200 символов). Текст книги, чанки и пункты оглавления в интернет не уходят. Каталога лент и своего URL ленты нет.

Nest качает RSS сам (`User-Agent` приложения, таймаут 15 с). Берёт `<item><title>`, снимает HTML, режет пробелы, выкидывает пустые и повторы. Не больше 24 заголовков, каждый не длиннее 200 символов.

Пустой канал, не-200 или обрыв сети — ошибка по-русски, строка в SQLite не создаётся, LLM не вызывается. Если область задана, пустой RSS не подменяется оглавлением.

Книги — второй вход, без сети. Nest читает уже сохранённый `Book.outline`. В ранжирование идут пункты, не чанки.

Нужно хотя бы одно: область или 1–5 книг. Книга должна быть `ready`. Чужая — `404`, не `ready` — `409`. Все выбранные оглавления пустые и области нет — та же понятная ошибка, без LLM.

### SQLite

Одна модель, JSON-строки как у `Book.outline` и `Post.bookIds`. Внешних ключей нет: удаление книги список тем не трогает.

```prisma
model TopicSearch {
  id        String   @id @default(cuid())
  area      String   @default("")
  bookIds   String   @default("[]")
  topics    String
  createdAt DateTime @default(now())
}
```

`topics` — JSON `[{ "title", "reason" }]`, 8–12 элементов. Пишется только успешный ответ. Сырые заголовки RSS не хранятся. `GET` отдаёт 30 последних, новые сверху.

### Nest

Префикса `/api` нет. Браузер по-прежнему говорит только с Nest.

| Метод | Путь | Контракт |
|--------|------|----------|
| `POST` | `/topics` | `{ area?: string, bookIds?: string[] }` → `201` карточка поиска |
| `GET` | `/topics` | `{ items: TopicSearch[] }`, до 30 |
| `DELETE` | `/topics/:id` | `204`. Нет записи — `404` |

Карточка: `{ id, area, bookIds, topics: [{ title, reason }], createdAt }`.

Ошибки до Python, по-русски:

- нет ни области, ни книг — `400` «Укажите область или книги.»
- область короче 2 или длиннее 200 — `400`
- книг больше 5 — `400`
- книга не найдена — `404`
- книга не `ready` — `409`
- RSS пустой — `502` «По этому запросу заголовков не нашлось.»
- сеть или разбор RSS — `502` «Не удалось получить заголовки.»
- FastAPI недоступен или модель не собрала список — `502` «Модель не собрала список тем.»

Nest не вызывает Ollama. После сборки входов зовёт FastAPI и ждёт лок GPU до 30 минут.

### FastAPI

`POST /topics/rank` — внутренний вызов Nest, не для браузера.

```json
{ "area": "привычки", "headlines": ["..."], "outline_items": ["..."] }
```

Один chat под `acquire("llm")`, `think: false`, temperature `0.3`. Системный промпт `ai-service/app/prompts/topics_system.md`. Ответ — JSON-массив `{ "title", "reason" }` на русском. Меньше 8 или неразобранный текст — ошибка `502`. Больше 12 — обрезать до 12. Заголовок до 200 символов, пояснение до 300. Новый тенант GpuManager не нужен.

### UI

Экран `/topics`, пункт «Темы» в сайдбаре сразу после «Библиотека».

Поле области и отметки книг в `ready`. Кнопка «Найти темы» на время запроса показывает ожидание и не гаснет из-за «GPU занят»: запрос ждёт тот же лок, что и остальные вызовы LLM. Успех дописывается сверху без повторного запроса при следующем заходе.

Клик по теме открывает `/create?topic=…`. Мастер один раз подставляет строку в поле темы. Правка поля запрос не затирает.

В библиотеке пункт оглавления — такая же ссылка на мастер. Раскрытие списка остаётся на заголовке «Оглавление».

## Решения этапа

- Заголовки: RSS-поиск Google News по области. Ключа нет. Ленты пользователь не заводит.
- Новый тенант GpuManager не нужен: ранжирование идёт тенантом `llm`.
- Успешный список — модель `TopicSearch`. Неудачный поиск в SQLite не пишется.

## Критерий приёмки

По запросу виден список тем. Клик подставляет тему в мастер. Пункт оглавления книги тоже становится темой. Генерация картинки и очередь постов ведут себя как до этапа.
